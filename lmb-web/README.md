# lmb-web 0.3.1 — кабинет врача

React 19 + TypeScript + Vite. Интерфейс работает поверх API `lmb-server`. Состав:

- **Вход.** Пароль и код второго фактора (TOTP). Если второй фактор не подключён, показывается экран подключения с QR-кодом.
- **Пациенты.** Поиск по полной фамилии или ИИН; ФИО, ИИН и контакты хранятся в зашифрованном виде.
- **Карточка пациента.** Список обследований; новый визит с датой обследования — от неё считается возраст во всех индексах.
- **Визит:**
  - «Анализы и измерения» — ввод с десятичной запятой, знаки «<» и «>», единицы по-русски. Исправление создаёт новую редакцию и требует причину; историю редакций можно открыть. Импортированные значения подтверждает или отклоняет врач.
  - «Анкета» — «Да / Нет / Не знаю»; «не знаю» хранится отдельно и не считается ответом «нет». Для CAIDE — физическая активность по определению шкалы и полные годы обучения (пустое поле = «не знаю»).
  - «FRAX» — что именно уйдёт в сервис (без идентификаторов пациента), запрос, выбор действующего результата, повтор после ошибки. Ручной ввод официального результата доступен и без заполненной анкеты: тогда врач явно выбирает «с МПК / без МПК», а результат помечается «анкета неполная». К результату можно приложить PDF или снимок; файл хранится только на сервере клиники в зашифрованном виде и скачивается из таблицы результатов.
  - «Профиль» — девять веток с индексами в их собственных единицах, статусами и причинами; под каждой веткой v0.3 — доменная оценка и Z-оценки входов (Z_raw; если ограничено ±3, показано «→ 3»). Итог LMB BioAge показывается только при полной утверждённой конфигурации; иначе выводятся причины. Есть проверка воспроизводимости расчёта.
- **Статусы** везде обозначены знаком, текстом и цветом. Поддерживаются тёмная тема и экран телефона.

## Разработка

```bash
npm install
npm run dev     # http://localhost:5173; запросы /api уходят на сервер 127.0.0.1:8000
npm run build   # сборка в dist/
```

## Сквозная проверка

Сценарий проходит в браузере Chromium через Playwright. Для запуска нужны собранный интерфейс, PostgreSQL 16 и Python-зависимости сервера:

```bash
npm run build && python3 e2e/run_e2e.py
```

Сценарий:

1. Неверный код второго фактора.
2. Вход.
3. Создание пациента.
4. Открытие визита.
5. Ввод 18 показателей.
6. Исправление показателя с причиной.
7. Заполнение анкеты.
8. Запрос FRAX — интеграция не подключена.
9. Ручной FRAX: недопустимое значение 140 % отклоняется.
10. Расчёт и проверка воспроизводимости.
11. Второй визит без анкеты: ручной FRAX с обязательным выбором «с МПК / без МПК» и файлом результата; файл на диске зашифрован и скачивается без изменений.
12. Ручной результат применяется в расчёте с предупреждением о неполных входах.
13. Проверка, что нет ошибок JavaScript.

Снимки экрана сохраняются в `e2e/screens/`. Все данные синтетические.
