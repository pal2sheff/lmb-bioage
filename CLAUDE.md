# LMB BioAge — инструкции для Claude Code

Сайт и калькулятор LMB BioAge для клиники Love my body (Казахстан). Владелец проекта — врач Абдували: он определяет медицинскую концепцию и утверждает изменения модели. Claude — основной разработчик.

Полный контекст владельца: `docs/LMB_Claude_Context.txt`. Техническое задание: `docs/LMB_BioAge_TZ_v1.0.docx`. При расхождении действует последнее поручение владельца; новое решение фиксируется с указанием, какое прежнее требование оно меняет.

## Как работать

- Пиши по-русски, профессионально и кратко, начинай с результата. Английские названия — только для продуктов, сокращений и кода.
- Документы: Times New Roman 12, по ширине, абзацный отступ 1,25 см, номер страницы, без других колонтитулов. Имена файлов — короткие, латиницей, без пробелов.
- Не заявляй, что функция реализована или проверена, без кода и пройденных тестов.
- После существенного изменения кратко фиксируй: что изменилось, что проверено, какой вопрос открыт.

## Медицинские ограничения (не нарушать)

1. **Не выдумывать** коэффициенты, нормативы, пороги, веса, таблицы баллов, возрастные эквиваленты, адреса и поля внешних API, коды стран. Отсутствующее помечается как отсутствующее; зависимый расчёт получает статус `model_not_configured` или `integration_not_configured`.
2. **Веса v0.3 неизменны:** `DeltaBioAge = 0.08 + 0.7·Cardio + 1.5·Metabolic + 1.3·Renal + 1.0·Hepatic + 1.4·Inflammation + 1.2·Brain + 0.9·Bone`; `LMB_BioAge = календарный возраст + DeltaBioAge`. Muscle и Adaptive: вклад `null`, статус `not_included` (это не ноль).
3. **Итог не считается** без полной утверждённой конфигурации (нормализация + правила объединения + все семь доменов). Нули и средние не подставляются, веса не перераспределяются. Доля ветки не считается делением на DeltaBioAge.
4. В формулу идут только доменные оценки, а не проценты риска, eGFR, FIB-4 или возраст LQ One.
5. «Неизвестно» ≠ «нет». Отсутствующее число — `null`, не 0.
6. Возраст — на дату обследования; границы применимости не подменяются ближайшей допустимой границей.
7. **FRAX не воспроизводится локально.** Только официальный сервис (FRAXplus API) или ручной ввод официального результата врачом. Во внешний FRAX не передаются ФИО, ИИН, контакты, адрес, внутренний ID пациента и дата рождения.
8. FRAX не используется для оценки эффективности лечения; изменение показателя не выдаётся за доказанный лечебный эффект или «омоложение».
9. Названия веток с «Age» не дают права выдавать годы. FRAX — не «костный возраст», CAIDE — не «возраст мозга».
10. Не воспроизводить внутренние алгоритмы LQ One и Visbody; SMM не подменяет массу мышц конечностей для ASMI.
11. Для разработки и демонстрации — только синтетические данные. Имитация внешнего ответа маркируется как тестовая и в клиническую базу не попадает.
12. Не покупать доступы и не обращаться к правообладателям (FRAXplus и др.) без отдельного поручения владельца.
13. Не менять самовольно состав веток, чекап, коэффициенты и правила расчёта.

## Структура репозитория

```
lmb-engine/   расчётный модуль на чистом Python (0.4.1): индексы, CAIDE, применимость, Z-оценки, домены, v0.3
lmb-server/   FastAPI + PostgreSQL 16 (0.5.0): роли, RLS, аудит, наблюдения, анкета, снимки, расчёты, FRAX, файлы
lmb-web/      React 19 + TypeScript + Vite 8 (0.4.0): кабинет врача и браузерный калькулятор (calc/); e2e на Playwright (Python)
docs/         ТЗ v1.0, контекст владельца, пакет параметров LMB_Claude_Data_1, сопоставление LQ One и Visbody
local/        тестовый режим на одном компьютере (Windows): install.bat/ps1, start/stop/backup.bat, lmb_local.py
```

Ключевые места:

- `lmb-engine/lmb_engine/indices.py` — реестр индексов; `cardio.py` — SCORE2/SCORE2-OP; `model.py` — нормализация, домены, интеграл, `attribute` (вклад ветки = вес v0.3 × доменная оценка и его разложение по показателям, считается и при заблокированном итоге, но не суммируется) и `trajectory` (Expected ±1 ResidualSD по возрасту в исходных единицах; обратный пересчёт значения в возраст запрещён); `pipeline.py` — порядок расчёта.
- `lmb-engine/config/model_v0.3.json` — конфигурация модели: веса v0.3, нормализация 12 показателей и правила доменов из `docs/LMB_Claude_Data_1.md` (11.10.2026); не хватает только `target_population`. `config/algorithms/score2*.json` — параметры SCORE2, `heartscore_verified: false`.
- `lmb-engine/tests/fixtures/heartscore_check.csv` — 30 случаев сверки с HeartScore (проверено 4). SCORE2 считает непрерывный возраст на дату обследования (как HeartScore); применимость и нормализация — по полным годам.
- `lmb-server/lmb_server/frax/` — сборка запроса (`request.py`), провайдеры (`providers.py`, класс `Mapping` намеренно не заполнен), очередь (`service.py`, `worker.py`).
- `lmb-server/lmb_server/storage.py` — файлы только на диске сервера, шифрование Fernet.
- `lmb-server/lmb_server/catalog.py` — справочник показателей и анкеты; `engine_bridge.py` — сборка снимка для движка.
- `lmb-server/migrations/versions/` — 0001–0006 (0006 — шифрование ФИО с переносом существующих карточек). Версия модели в базе хранится неизменяемыми редакциями (`label` + `revision`); изменение конфигурации = новая редакция через миграцию, прежняя → `archived`. Новые таблицы с данными клиники требуют RLS (`ENABLE`/`FORCE`, политика по `lmb.clinic_id`) и явных `GRANT` для `lmb_app`; см. 0003 и 0004.
- `lmb-web/calc/`, `lmb-web/src/calc/` — браузерный калькулятор (решение владельца 11.10.2026: тестовый режим в браузере, «как МИТОпаспорт»): статический сайт, `lmb_engine` и `config/` выполняются в Pyodide без изменений (`scripts/export_engine_bundle.py` копирует файлы, `src/calc/bridge.py` — вход/выход JSON). Формулы в TypeScript не дублировать. Данные не покидают браузер (сохранение — в файл). Отображение профиля общее с кабинетом врача: `src/components/ProfileView.tsx`, графики — `src/components/Charts.tsx` (вклад 7 систем, вклад показателей, траектории; цвета `--up`/`--down` проверены на CVD). В шапке калькулятора нет служебных надписей (решение владельца 11.10.2026); версии модуля и конфигурации пишутся в сохраняемый файл случая. Публикация — `.github/workflows/pages.yml` (GitHub Pages; нужно включить Pages в настройках).
- `local/lmb_local.py` — запуск без Docker: своя база PostgreSQL в `%LOCALAPPDATA%\LMB-BioAge` (trust, только 127.0.0.1), ключи в `secrets.env` там же, сайт на 127.0.0.1:8000, TOTP выключен (`LMB_REQUIRE_STAFF_TOTP=false`), FRAX — ручной ввод. CI проверяет этот запуск на windows-latest.

## Архитектурные правила

- Расчёты — только в `lmb-engine`, независимо от экранов и языковой модели. Никакого `eval` и исполняемых формул из админки.
- Исходные наблюдения отделены от результатов. Исправление создаёт новую редакцию с автором, временем и причиной.
- Каждый расчёт ссылается на неизменяемый снимок входов (SHA-256) и версии модуля, модели и алгоритмов; `reproduce` должен давать тот же результат.
- Изоляция клиник в два слоя: фильтр в коде (чужое → 404) и RLS PostgreSQL. Роль `lmb_app` без BYPASSRLS, не удаляет медицинские записи, аудит — только добавление.
- Изменяющие запросы: CSRF-заголовок `X-CSRF-Token`, `Idempotency-Key` для создания, `If-Match` для изменения карточки. В мутирующих эндпоинтах явный `db.commit()`.
- Результат FRAX привязан к хешу входов. Автоматический результат не заменяет действующий ручной. Ручной ввод работает и без анкеты (`inputs_bound = false`, предупреждение в Bone).
- Файлы: только локальный диск `LMB_FILES_DIR`, шифрование ключом `LMB_FILES_KEY`, тип по содержимому (PDF/PNG/JPEG), права 0600/0700, проверка SHA-256 при выдаче.

## Запуск и проверки

Нужны Python ≥ 3.11, PostgreSQL 16 (бинарники `initdb`/`pg_ctl` в PATH или `/usr/lib/postgresql/16/bin`), Node 22, Chromium для Playwright. Docker не требуется.

```bash
# движок
cd lmb-engine && pip install -e . pytest pytest-cov && python3 -m pytest -q
# сервер (сам поднимает временный кластер PostgreSQL, применяет миграции)
cd lmb-server && pip install -e ".[test]" && python3 -m pytest -q
# интерфейс + сквозной сценарий
cd lmb-web && npm install && npm run build && pip install playwright && python3 e2e/run_e2e.py
```

Состояние на 11.10.2026: движок — 202 теста пройдено, 26 пропущено (непроверенные случаи HeartScore); сервер — 109 тестов; e2e кабинета — 13 шагов; e2e браузерного калькулятора — 7 шагов (`npm run calc:bundle && npm run calc:build && python3 e2e/run_calc_e2e.py`). 11.10.2026 один прогон серверных тестов из 12 завершился одной ошибкой, которая не повторилась (вероятно, нестабильный тест); при повторении запустить `pytest -rf` и зафиксировать имя теста. Под root кластер PostgreSQL запускается от пользователя `postgres` в `/var/tmp`. Для ускорения тестов `LMB_ARGON2_PROFILE=test` (только в тестах).

Миграция: изменить модели → `alembic revision --autogenerate --rev-id 000N` при поднятой базе (см. `tests/pgcluster.py`) → дописать RLS и GRANT вручную → проверить `alembic downgrade` и `alembic check`.

Переменные сервера: `LMB_DATABASE_URL`, `LMB_ADMIN_DATABASE_URL`, `LMB_FIELD_KEY`, `LMB_INDEX_KEY`, `LMB_FILES_DIR`, `LMB_FILES_KEY`, `LMB_MAX_UPLOAD_MB`, `LMB_COOKIE_SECURE`, `LMB_REQUIRE_STAFF_TOTP`, `LMB_STATIC_DIR`, `LMB_FRAX_*` (см. `lmb-server/README.md`).

## Открытые решения владельца

1. **ФИО — решено 11.10.2026:** шифруется (как ИИН и контакты). Поиск — по полной фамилии через слепой индекс (без учёта регистра и ё/е) или по ИИН; поиск по началу фамилии невозможен, сортировка по алфавиту — после расшифровки.
2. **FRAX «предполагаемое нет»:** настройка `LMB_FRAX_ALLOW_ASSUMED_NO`, по умолчанию выключена.
3. **SCORE2:** проверено 4 из 30 случаев HeartScore (совпали). Заполнить остальные 26 в `lmb-engine/tests/fixtures/heartscore_check.csv` (порядок — README движка), затем `heartscore_verified: true`. До этого домен Cardio не считается.
4. **FRAXplus:** лицензия, действующая спецификация API, код Казахстана, класс `Mapping`; облако или локальный Docker — после правовой проверки передачи данных.
5. **CAIDE:** таблица модели 1 получена от владельца 11.10.2026 и реализована; применимость 39–64 полных лет.
6. **Модель v0.3:** нормализация и правила доменов получены (LMB_Claude_Data_1). Не хватает целевой популяции и режима выдачи исследовательского результата. LMB_Claude_Data_2.docx (11.10.2026) побайтно совпадает с Data_1 — новых данных нет. Найденные свойства коэффициентов (вынесены владельцу 11.10.2026, коэффициенты не менялись): Expected SCORE2 в 3–5 раз ниже типичных значений SCORE2 региона high — Z Cardio ≈ +1,5…+3,4 даже при благоприятном профиле, после 60 лет при обычных значениях часто превышает +3 и обрезается; CAIDE содержит ступенчатые баллы возраста, а Expected — линейный возраст, поэтому в 47 лет Delta скачком растёт примерно на 2,8 года, в 54 — примерно на 0,9 года без изменения здоровья. Возраст в нормализации — полные годы (уточнить у владельца).
7. **LQ One и Visbody:** образцы получены 10.10.2026, поля сопоставлены в `docs/device_mapping.md`. Итоговый показатель LQ One — «Биологический возраст», годы. Открыто: порог достоверности LQ One, смысл «МСМ» Visbody, допустимость суммы сегментов конечностей как ASM, источник талии для WHtR, часовой пояс Visbody, модель и версии устройств, PDF LQ One. Образцы — реальные данные пациента: в репозиторий и тесты не класть. Лабораторные файлы ещё не получены.
8. **Правовая проверка отложена (решение владельца 11.10.2026):** система работает в тестовом режиме на компьютере владельца (Windows, `local/`). Перед рабочим использованием с пациентами клиники и перед подключением внешнего FRAX вопросы размещения, оснований обработки и сроков хранения нужно вернуть.
